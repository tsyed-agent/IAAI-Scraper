Project Vision

What we're building, why it matters, and the features we're seeking to accomplish — in plain language.

Mission

Build a reliable internal data collection system for IAA/IAAI Canada vehicle auctions, scoped to Ontario. The system collects structured auction lot data, stores it in a searchable database, and exposes it through an internal API — optimized for completeness, speed, reliability, and cost. Images are intentionally not collected.

What We're Trying to Accomplish

Never Go Stale

Maintain a permanent historical archive of every Ontario lot and what it sold for. Full metadata snapshots every 12 hours; pricing as close to real-time as free infrastructure allows.

Future goal

Complete Ontario Coverage

Capture all ~1,450 active lots across 7 Ontario branches (London, Toronto, Hamilton, Ottawa, Sudbury, and more) with every available field preserved.

Working today

Searchable & Filterable

Query lots by make, model, year, branch, damage, title type, sale status, and more through a clean internal API — no manual browsing of the IAAI website.

Working today

Cost-Efficient & Sustainable

Run on completely free infrastructure. Ontario-only scope, no image downloads, incremental updates, and deduplication keep bandwidth and storage minimal.

In progress

Core Features

  • Automated lot collection — Crawl IAAI Canada auction listings without manual intervention, passing anti-bot protections automatically.
  • Structured data storage — Every lot normalized into a typed schema with full raw payload preserved for audit and re-parsing.
  • Lifecycle tracking — Know whether a lot is active, sold, if-bid, passed, or removed from inventory.
  • Price awareness — Capture pre-bids, timed auction bids, buy-now prices, and final sale outcomes.
  • Internal read API — FastAPI endpoints for querying, filtering, sorting, and retrieving individual lots.
  • Historical archive — Lots are never deleted; sold and delisted vehicles remain queryable forever.
  • Price history time series — Track how a lot's price moved over time (planned — not yet built).
  • Scheduled refresh — Automatic periodic crawls at full-metadata and price-only cadences (planned).

Design Principles

Completeness

Capture every available lot field. Nothing silently dropped — the full raw row is always preserved alongside normalized columns.

Speed

Solve the anti-bot challenge once per session, then fetch fast. Ontario-at-source filtering cuts requests by 25×.

Reliability

Idempotent, resumable, observable. Survives blocks and restarts with automatic re-solve and retry logic.

Cost Efficiency

Ontario-only, no images, incremental upserts, dedup. Designed to run sustainably on free infrastructure.

What We're NOT Building

  • Image collection or download (URLs preserved in raw data only)
  • Public-facing product or consumer UI
  • Full VIN access (masked for anonymous users; requires logged-in buyer account)
  • Official IAAI API integration (no public API exists — we scrape)

Crawl Strategy

Current (Built)

  • Crawl all Canada (~53 pages × 100 rows)
  • Filter to 7 Ontario branches client-side
  • Sort by STOCK ASC (zero page overlap)
  • ~4m24s for full Ontario set (1,448 lots)
  • In-page fetch() via Playwright session

Target (Doc 06)

  • BranchIds filter at source (Ontario only)
  • PageSize=1000 (2–3 requests total)
  • ~20–30s for full Ontario snapshot
  • Two cadences: full (12h) + price (2–15 min)
  • Warm session reuse between refreshes
